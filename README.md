# 내내 (nae nae) MVP 0.5 — 개발자 검토용

> 서비스명 **내내 (nae nae)** · 한글 슬로건 “좋은 기억을 내내” · 영문 슬로건 “With Music, With You, Always” — `config.js`에서 변경, 로고 `assets/logo.png`(보라) · `assets/logo-white.png`(인증샷용)

> 상태: **배포 직전(미배포)**. 개발자 컨펌 → KOPIS 키·Apps Script 연결 → 운영자 공지 입력 → `node tools/check.mjs` 통과 → 배포

## 1. 범위
| 메뉴 | 기능 |
|---|---|
| 오픈 공지 (홈) | 티켓 오픈 공지 **리스트 / 월 캘린더** 전환, **내 캘린더에 추가**(구글 캘린더 링크 · .ics), 보고 싶어요, 예매처 이동 |
| 공연 일정 | KOPIS 공연 목록(대중음악), 검색·지역·라이브클럽 필터, 상세(출연진 관심 담기, 보고 싶어요, 관람했어요) |
| 나의 라이브 | 보고 싶은 공연 · 관람 완료 · 관심 아티스트, 직접 기록, **취향 배지** (`lib.js computeBadges`, 규칙표 `BADGE_RULES`, 컨셉 `BADGE_CONCEPTS`, 화면 `#/badges` 가이드)
- 세 가지 기록(🎫 관람 완료 · 💜 관심 아티스트 · 👀 보고 싶은 공연)으로 다섯 축의 배지
  | # | 축 | 배지 | 이모지 | 재료 | 이달 | 연말 결산 |
  |---|---|---|---|---|---|---|
  | 1 | 유형 | 대표 (올라운더🌈·프로직관러🔥·디거🔍·레이더📡) | 유형별 | 세 기록의 비율 | 합계 3+ | 3+ |
  | 2 | 공간 | ○○ 단골 | 💡 | 관람·보고싶은 공연의 공연장 | 2+ | 3+ |
  | 3 | 사람 | ○○ 찐팬 | 💜 | 관람한 공연의 아티스트 | 2+ | 3+ |
  | 4 | 거리 | 원정러 → 장거리 원정러 | 🚌 → 🚄 | 지방(서울·경기·인천 외) 공연 | 1+ / 3+ | 2+ / 5+ |
  | 5 | 횟수 | 관람완료 N회 | 🎤 | 그 기간에 본 공연 수(관람했어요 + 직접 기록) | 3+ | 12+ |
- **매월 갱신**(관람=관람일, 보고싶어요·관심=담은 날) · **연말 결산**은 12월 1일 공개, 12월엔 기본 화면
- 이모지는 기기 기본 이모지 글꼴로 표시 → OS마다 그림이 조금 다름. 디자인 외주 시 같은 컨셉으로 그림 교체 가능(`BADGES`, `BADGE_CONCEPTS`의 emoji 필드)

**기록 저장**: localStorage(`ml05_records`, `ml05_artists`) — 로그인 없음, 기기·브라우저 단위. 0.3 키와 호환하지 않음(0.3 미배포).

## 4-1. 로그인 · 회원가입 (`#/login`, `#/signup`)
- 화면: 카카오·네이버·Google 버튼 + 이메일 로그인/가입, 약관(만 14세 이상·이용약관·개인정보 필수, 마케팅 선택), 입력 검증
- **현재 인증 서버 없음** (`config.js auth.provider: 'none'`) → 제출해도 **정보를 저장·전송하지 않고** "정식 오픈 때 열려요" 안내. 시도 횟수만 익명 이벤트(`login_attempt`, `signup_attempt`, 값=방법)로 기록 = 회원 기능 수요 측정
- 연결 방법(개발자): 인증 서비스(예: Supabase Auth, Firebase Auth, 카카오 로그인) 선택 → 아래 어댑터를 `auth.js`로 만들어 `app.js` 앞에 로드 → `auth.provider` 값 변경
  ```js
  window.NaeAuth = {
    async signUp({ email, password, nickname, marketing }) { /* 가입, 실패 시 throw new Error('사용자에게 보일 문구') */ },
    async signIn({ email, password }) { /* 로그인 */ },
    async social(provider) { /* 'kakao' | 'naver' | 'google' 리다이렉트 */ },
    async signOut() {}, current() { return null; }
  };
  ```
- 로그인 후 할 일(다음 단계): localStorage 기록(`ml05_records`, `ml05_artists`)을 계정으로 옮기는 동기화
- **오픈 전 필수**: 이용약관·개인정보 처리방침 문서(운영자), 카카오·네이버 공식 버튼 디자인 가이드 적용, 개인정보 수집 항목 최소화(이메일·닉네임·동의 이력)

## 5. Apps Script (구글 시트 1개)
1. 기록용 구글 시트 → 확장 프로그램 → Apps Script → `apps-script/Code.gs` 붙여넣기
2. 프로젝트 설정 → 스크립트 속성 `KOPIS_KEY` = 서비스키 (**사이트 코드에 넣지 않음**, 점검 스크립트가 감시)
3. `installTriggers` 실행 → 매일 06:00 `syncKopis`
4. `syncKopis` 수동 실행 → `kopis` 시트 확인
5. 배포 → 웹 앱(실행: 나, 액세스: 모든 사용자) → URL을 `config.js appsScriptUrl`에
6. 브라우저에서 `…/exec?type=performances` 열어 JSON 확인

`syncKopis`: 오늘~60일, 31일 단위로 목록 조회(`shcate=CCCD` 대중음악, 100건씩 페이지) → 새 공연만 상세 조회(출연진 `prfcast`, 예매처 `relates`) 최대 150건/회 → 시트 저장 → doGet은 10분 캐시.

## 6. 개발자에게 확인 요청
- [ ] **KOPIS 실제 응답 검증** — 이 코드는 KOPIS 키 없이 작성했습니다. 엔드포인트, `shcate=CCCD`, 조회 기간 제한(31일 가정), 상세의 `prfcast`·`relates/relate/relatenm,relateurl` 필드명을 실제 응답으로 확인해 주세요. **미검증**
- [ ] KOPIS 이용 조건(상업적 이용, 출처 표기, 호출 제한) — 화면 하단에 출처 표기 넣어 둠
- [ ] Apps Script doGet을 브라우저에서 fetch할 때 CORS 동작 (일반적으로 허용되나 실배포 확인 필요)
- [ ] 아이폰 Safari에서 .ics 다운로드 → 캘린더 추가 화면, 안드로이드에서 .ics 처리(기본 캘린더 앱마다 다름)
- [ ] 인스타 앱 내 브라우저에서 .ics·사진 저장 동작 (안내 배너 있음)
- [ ] 인증샷 실기기 공유(0.4와 동일 항목)
- [ ] 라이브클럽 필터 기준(`config.js clubVenues`) — 운영자 확정 필요
